# AI README for PokeSnap-Dex

## Overview
PokeSnap-Dex is a web-based Pokémon photo collection app inspired by Pokémon GO's AR photo feature. It displays a grid of 1025 Pokémon (Gen 1–9 with variants) with thumbnails. Users can click thumbnails to open a gallery modal for viewing variants and Pokédex entries, search Pokémon, toggle themes, and see a capture count. The app uses vanilla HTML, CSS, and JavaScript with two JSON data files. **No frameworks, no build step, no bundler.**

## UI Design Rules
- **Layering**: Header and footer are always on top of dex-container (z-index: 1000). Header and footer share the same layer.
- **Widths**: Header, footer, and dex-container have matching visual widths (100% of #app-container, with box-sizing: border-box for dex-container to include padding).
- **Sticky Elements**: Header sticks to top, footer sticks to bottom.
- **Responsive Height**: Dex-container uses `height: calc(100vh - 100px)` to fill available space, capping rows before footer.
- **Box-Sizing**: Dex-container uses `box-sizing: border-box` to ensure padding doesn't affect total width.

## File Structure
- **`index.html`**: Main HTML structure. Includes header with controls (search, theme toggle, captured count), main grid container (`#dex-container`), and modals (gallery, captured list).
- **`styles.css`**: CSS for layout (grid, flexbox), themes (dark/light), responsive design (mobile breakpoints), gallery modal styling, and animations.
- **`script.js`**: All app logic — data loading, grid rendering, gallery modal, keyboard nav, dex entry display. No dependencies.
- **`data.json`**: Pokémon image/variant metadata (1025 entries — name, variants array, genus). **Never contains embedded dex entry text.**
- **`data-entries.json`**: Externalized Pokédex entry text, generated by `scripts/sync-dex-entries.js`. Schema v2. **Source of truth is PokeAPI; do not manually edit this file.**
- **`scripts/sync-dex-entries.js`**: Node.js CLI that fetches all 1025 species from PokeAPI, generates `data-entries.json`, strips any lingering embedded entries from `data.json`, and normalizes variant ordering.
- **`test.js`**: Node.js integrity suite — 99 name/format assertions, position array validation, capture count logic, and `data-entries.json` schema validation.
- **`BRANCH_NOTES.md`**: Branch-specific guidance (never merge `data.json` from `main` to `LitoFrito`).
- **`README.md`**: User-facing setup and customization docs.

## Data Structure

### `data.json`
Object keyed `"001"` to `"1025"`. Each entry:
```json
{
  "name": "Bulbasaur",
  "genus": "Seed Pokémon",
  "variants": [
    {
      "image": "https://i.imgur.com/xxxxx.png",
      "label": "Bulbasaur",
      "position": "center",
      "fit": "contain"
    }
  ]
}
```
- `label` is the display name shown in the gallery (e.g. `"Shiny Charizard"`, `"Mega Charizard X"`).
- Placeholders use `"https://your-image-url-here.jpg"`. Thumbnails skip placeholders.
- `genus` is populated automatically by `sync-dex-entries.js` from PokeAPI and shown in the gallery header.
- **Variant ordering rule**: Regular form first, then Mega/regional/shiny variants (see BRANCH_NOTES.md for ordering conventions).
- **Consistency rule**: Any new variant label added to `data.json` must also be added to the matching dex-entry source if it needs a specific Pokédex entry. For form variants not in PokeAPI, use `data-entries-overrides.json` with the exact same label string.
- **Required validation**: After changing variant labels, run `node test.js` and confirm the matching dex lookup works for both the regular and shiny form names.

### `data-entries.json`
Generated file. Schema v2:
```json
{
  "_meta": { "schemaVersion": 2, "generatedAt": "...", "totalEntries": 14496 },
  "entries": {
    "001": {
      "default": [
        { "source": "Red", "text": "A strange seed..." }
      ],
      "defaultGrouped": [
        { "source": "Red/FireRed", "text": "A strange seed..." }
      ]
    }
  }
}
```
- `default`: flat array of `{source, text}` objects, one per game version.
- `defaultGrouped`: same entries after deduplication — games with identical (normalized) text are merged into a slash-joined source label.
  - Remake pairs collapse: e.g. `Red + FireRed → (Fire)Red`, `Gold + HeartGold → (Heart)Gold`.
  - Sequel pairs collapse: e.g. `Black + Black 2 → Black (2)`.
- `variants` and `variantsGrouped` (optional): reserved for form-specific entry maps keyed by variant label. **Currently unused.** These keys will only appear if a future data pipeline produces form-specific entries from PokeAPI.
- **Do not manually edit this file.** Regenerate with `node scripts/sync-dex-entries.js`.

## Key Components and Logic

### HTML Structure
- **App Container**: `#app-container` wraps everything.
- **Header**: Sticky header with title, controls (search input, captured count button, theme toggle), and divider.
- **Dex Container**: `#dex-container` holds the Pokémon grid (CSS grid with auto-fit).
- **Gallery Modal**: `#gallery` (hidden by default) shows large image, name, genus, dex entries, and navigation buttons (prev/next/close).
- **Captured Modal**: `#captured-modal` for viewing captured Pokémon list.

### CSS Classes and Styling
- **Themes**: `.dark-mode` toggles dark/light styles (backgrounds, colors).
- **Grid**: `#dex-container` uses `grid-template-columns: repeat(auto-fit, minmax(192px, 1fr))` for responsive layout.
- **Gallery**: Fixed positioning (`position: fixed`) with `z-index: 2000` to overlay. Images sized at 50% width/height, with `object-fit` for cropping.
- **Responsive**: Media queries adjust header layout, button sizes, and grid min-width for mobile.
- **Entry States**: `.entry.empty` for missing images (black box with name).

### JavaScript Logic (`script.js`)

#### Initialization (`DOMContentLoaded`)
- Loads `data.json` and `data-entries.json` via `fetch` in parallel.
- Calls `renderDex()` to populate grid.
- Sets up event listeners (search, theme toggle, gallery close, keyboard navigation).

#### Data Loading and Rendering
- **`renderDex()`**: Loops through `pokedexData`, creates `<div class="entry">` for each Pokémon. Sets thumbnail to first non-placeholder variant. Adds click handler to `openGallery(number)`.
- **Thumbnail Logic**: Finds first variant with real image URL. Sets `background-image` and `object-position` for cropping. If no image, shows name in black box.

#### Gallery Modal
- **`openGallery(number)`**: Sets current Pokémon, finds first real variant, updates image/name/entries, shows modal.
- **`updateGalleryImage()`**: Updates image src, alt text, name, genus, styling (position, fit, background), and dex entries.
- **Navigation**: `prev-variant`/`next-variant` buttons cycle through variants. `close-gallery` hides modal.

#### Keyboard Navigation
- `Left` / `Right`: navigate images within the current Pokémon.
- `Ctrl+Left` / `Ctrl+Right`: jump to previous/next Pokémon in the dex.
- `Up` / `Down`: scroll through dex entries for the current gallery image.
- `Escape`: close the gallery.
- Shared helpers: `navigateGalleryImage(delta)`, `navigateGalleryEntry(delta)`, `closeGalleryModal()`.

#### Dex Entry Display
Entries are loaded from `data-entries.json` into `dexEntriesByNumber` keyed by dex number.

Lookup chain for a given variant label (most-specific wins):
1. `variants[label]` (form-specific flat list, currently unused)
2. `variantsGrouped[label]` (form-specific grouped list, currently unused)
3. `defaultGrouped` (species-level grouped entries) ↓ **this is always hit today**
4. `default` (species-level flat entries)
5. `[]` (empty — no entries available)

Shiny fallback: `getVariantLabelCandidates(label)` strips a `"Shiny "` prefix as a secondary candidate so that `"Shiny Mega Charizard X"` falls back to `"Mega Charizard X"` form-specific entries if they ever exist.

Key entry helpers:
- `normalizeEntryItem(item)`: coerces string or `{source, text}` to always return `{source, text}`.
- `getVariantLabelCandidates(label)`: returns `[label, baseLabel]` array.
- `getVariantEntries(entryMap, candidates)`: tries each candidate label, returns first match.
- `getEntriesForVariant(number, variantLabel)`: full lookup chain described above.

#### Search and Filtering
- **`search-input`**: On input, filters entries by name and variant label (case-insensitive) and hides non-matching entries.
- Multiple entries can be retrieved with commas: `Pikachu, Gastly`.
- Search is case-insensitive.
- Bare `Shiny` returns all captured shiny variants and prefers shiny images in the grid.
- `Shiny <Pokemon>` returns that specific shiny while leaving other comma terms regular.
- `Shiny & <Pokemon1>, <Pokemon2>` or `Shiny and <Pokemon1>, <Pokemon2>` applies shiny to all listed names.
- `Shiny <Pokemon1>, <Pokemon2>` mixes shiny and regular results: shiny for the first name, regular for the second.
- For 1–2 results, the layout switches to centered flex.

#### Theme Toggle
- **`theme-toggle`**: Toggles `dark-mode` class on `body`. Persists in `localStorage`.

#### Capture Count
- **`updateCapturedCount()`**: Counts Pokémon with at least one non-placeholder variant. Updates button text and enables captured modal.

#### Other Features
- **Captured Modal**: `captured-count` click shows list. `toggle-show-all` toggles showing all vs. captured.
- **Power Indicator**: Visual element in header (no functionality).
- **Responsive**: JS adjusts grid on window resize.

## Dex Entries System

### Philosophy
`data-entries.json` is **API-generated only**. The sync script is the single source of truth. Never manually populate or patch it — any edits will be overwritten on the next sync run.

### Sync Script (`scripts/sync-dex-entries.js`)
Run: `node scripts/sync-dex-entries.js`

- Fetches `/pokemon-species/{1..1025}` from PokeAPI with 10x concurrency and up to 3 retries per request.
- **UTF-8 safety**: Collects raw `Buffer` chunks and decodes once to prevent multi-byte character corruption from chunk-split HTTP streams.
- Builds `default` (flat) and `defaultGrouped` (deduplicated) entry arrays per species.
- Strips any lingering embedded entry text from `data.json`.
- Normalizes variant ordering in `data.json` (regular form first).
- Writes genus back into `data.json` for every species.
- Writes `data-entries.json` (schema v2).

### Grouping Logic (`buildGroupedEntries`)
- Groups entries by normalized text key (`normalizeTextForGrouping`): strips accents, lowercases, stems plural suffixes for words ≥4 chars, collapses non-alphanumeric. Handles legacy `POKéMON`/`BULBASAUR` all-caps variants.
- Chooses best display text via `chooseGroupedDisplayText` (prefers most-recent casing/punctuation).
- Source labels normalized by `normalizeGroupedSourceLabel`:
  - Remake pairs: `(Fire)Red`, `(Heart)Gold`, `(Soul)Silver`, `(Omega)Ruby`, `(Alpha)Sapphire`, `(Brilliant)Diamond`, `(Shining)Pearl`
  - Sequel pairs: `Black (2)`, `White (2)`, `X (2)`, `Y (2)`, `Sun (2)`, `Moon (2)`, `Sword (2)`, `Shield (2)`

### Form-Specific Entries
The `variants` / `variantsGrouped` schema keys are reserved in `data-entries.json` and the app-side lookup chain is fully wired, but **no form-specific data is currently populated** because PokeAPI does not expose per-form Pokédex text. All gallery views fall through to `defaultGrouped`. If a future data source is added (separate issue), the infrastructure is ready.

### Required Override Workflow for New Forms
When a form or variant is added to `data.json` but does not exist in the default PokeAPI entry set, treat it as a required follow-up task:
1. Add the exact label text to `data.json`.
2. Add the same label text to `data-entries-overrides.json` under the matching species number.
3. Mirror the shiny version with the same pattern (`Shiny <Label>`).
4. Match the wording exactly; the UI resolves dex text by label match, so mismatches silently fail.
5. Run `node test.js` before closing the issue.

This is required for forms like Unown, Keldeo - Resolute Form, and Cramorant - Gulping/Gorging Form. The override file is the safety net for species-specific forms that PokeAPI leaves out.

## Workflows
1. **Page Load**: Fetch `data.json` + `data-entries.json` → Render grid → Set up listeners.
2. **Thumbnail Click**: Open gallery → Show first real variant → Allow image + entry navigation.
3. **Search**: Filter grid → Update layout for few results.
4. **Theme Change**: Toggle class → Update styles.
5. **Capture Check**: Count real images → Update UI.

## Branch Differences
- **`main`**: Public branch with placeholder images in `data.json`. Deployed to GitHub Pages.
- **`LitoFrito`**: Personal branch with real Imgur URLs in `data.json`.
- Create fix branches from `main` for bug fixes and feature work.
- After approval, merge the fix branch into `main`.
- Then propagate the same fix to `LitoFrito` while preserving real `data.json` image URLs.
- `main` and `LitoFrito` should be synchronized on all issue fixes and new features outside of real image URIs.
- The only intentional differences are real `data.json` image URLs and `data-entries.json` content on `LitoFrito`.
- See `BRANCH_NOTES.md` for merge rules.
- Remote is named `GitHub`.

## Common Tasks
- **Add Pokémon images**: Update `data.json` with real image URLs.
- **Regenerate dex entries**: `node scripts/sync-dex-entries.js` (requires internet; ~2-3 min).
- **Run tests**: `node test.js`.
- **Serve locally**: `python3 -m http.server 8000`.
- **Deploy**: Push to GitHub, enable Pages on the desired branch.
- **Propagate UI changes** from LitoFrito to main: cherry-pick or diff-apply non-data files only; never touch `data.json` on main.
 
## Notes for AI
- Use `fetch` for data loading (no libraries).
- Gallery uses DOM manipulation for modal (no frameworks).
- Positioning (`left`, `right`) crops images for variants (e.g., Gastly shares image).
- Use atomic commits for issue fixes and include a note in the commit message that the issue is being closed (for example: `closes #55`).
- Avoid upscaling images in gallery to prevent pixelation.
- For changes, update both branches if UI-related, but keep `data.json` separate.
- `data-entries.json` is in `.gitignore` on `main` (placeholder branch has no entries). It is committed on `LitoFrito`.
